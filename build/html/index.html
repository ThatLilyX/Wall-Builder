Welcome to Wall Builder’s documentation!

This is a Python package for solving the Wall Builder problem. Please follow the instructions below to install the package and execute the main function.

Install Anaconda Environment with Python 3.10

To build the Anaconda environment, run the following command in the terminal:

$ conda env create -f src/environment.yml

To activate the environment, run the following command in the terminal:

$ conda activate general-py3.10

For more information on managing the Anaconda environment, please refer to Anaconda documentation.

Execute wall_builder

The main function for solving the given problem is as follows:

class wall_builder.num_wall_layouts(brick_set: set, wall_length: int, wall_height: int, predicate=<function no_common_edge>)[source]

Return the number of all possible wall layouts given a brick set, wall dimensions and given eligibility predicate of neighboring rows.

Assumptions:

  • there’re unlimited supply of bricks of each size

  • only use bricks horizontally

The algorithm is broken down into three steps:

  1. Find all possible row layouts using Dynamic Programming (see row_layouts_dp())

  2. Find eligible neighbors for each row layout according to the given predicate (see build_neighbors())

  3. Find the number of all possible wall layouts using Dynamic Programming (see num_wall_layouts_helper())

Parameters:

  • brick_set (set) – available bricks; each element is the length of a brick

  • wall_length (int) – length of the wall

  • wall_height (int) – height of the wall

  • predicate (function) – a function that takes in two row layouts’ index and other keyword arguments, and returns True if they are eligible neighbors

Returns:

the number of all possible wall layouts

Return type:

int

Results & Tests

Result of the given example

For the given brick_set (set([2, 3])), wall_length (30) and wall_height (12), the number of possible wall layouts is 16879522589829476.

To confirm the above result, you can run wall_builder.wall_layout or call wall_builder.num_wall_layouts() with the given parameters.

Unit tests

Unit tests are written in /test folder with pytest. The pytest-metrics plugin is used to generate a report pytest_metrics.html with the test results. You can regenerate it when you run these tests.

Hypothesis testing is attempted with Hypothesis to generate random test cases. However, given the complexity of the problem, it can take a long time to execute all of them, so they are commented out in the test_row_layout.py file.

Despite that, almost all test cases (- except for test_wall_layout.py due to complexity) are written in the style of Property-based testing, which is supposed to be more robust than Example-based testing.

Profiling

The performance of functions can be profiled with the decorator @profile defined in wall_builder.utils.profiler. It will generate a .prof file for the decorated function in the /prof folder. This file can be visualized with snakeviz by running the following command in the terminal:

$ snakeviz prof/<function_name>.prof

For more information on snakeviz, please refer to snakeviz documentation.

Given that the algorithm of this problem is pretty straightforward, the profiler didn’t show its advantage as seen in other large projects.
