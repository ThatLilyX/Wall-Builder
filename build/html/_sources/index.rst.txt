Welcome to Wall Builder's documentation!
========================================

This is a Python package for solving the Wall Builder problem. 
Please follow the instructions below to install the package and execute the main function.

Install Anaconda Environment with Python 3.10
==============================================

To build the Anaconda environment, run the following command in the terminal:

.. code-block:: bash

    $ conda env create -f src/environment.yml


To activate the environment, run the following command in the terminal:

.. code-block:: bash

    $ conda activate general-py3.10

For more information on managing the Anaconda environment, please refer to 
`Anaconda documentation <https://docs.conda.io/projects/conda/en/latest/user-guide/tasks/manage-environments.html>`_.

Results & Tests
===============
Result of the given example
----------------------------

For the given ``brick_set`` (``set([2, 3])``), ``wall_length`` (``30``) and ``wall_height`` (``12``), the number of possible wall layouts is ``16879522589829476``.

To confirm the above result, you can run :py:mod:`wall_builder.wall_layout` or call :py:func:`wall_builder.num_wall_layouts` with the given parameters.

Unit tests
----------

Unit tests are written in ``/test`` folder with ``pytest``. The `pytest-metrics <https://github.com/adiralashiva8/pytest-metrics>`_ plugin is used to generate a report 
``pytest_metrics.html`` with the test results. You can regenerate it when you run these tests.

Hypothesis testing is attempted with `Hypothesis <https://hypothesis.readthedocs.io/en/latest/>`_ to generate random test cases. However, given the complexity of the problem,
it can take a long time to execute all of them, so they are commented out in the ``test_row_layout.py`` file. 

Despite that, almost all test cases (- except for ``test_wall_layout.py`` due to complexity) are written in the style of 
`Property-based testing <https://increment.com/testing/in-praise-of-property-based-testing/>`_, 
which is supposed to be more robust than Example-based testing.

Profiling
---------

The performance of functions can be profiled with the decorator ``@profile`` defined in :py:mod:`wall_builder.utils.profiler`. 
It will generate a ``.prof`` file for the decorated function in the ``/prof`` folder. 
This file can be visualized with ``snakeviz`` by running the following command in the terminal:

.. code-block:: bash

    $ snakeviz prof/<function_name>.prof

For more information on ``snakeviz``, please refer to `snakeviz documentation <https://jiffyclub.github.io/snakeviz/>`_.

Given that the algorithm of this problem is pretty straightforward, the profiler didn't show its advantage as seen in other large projects.

About this documentation
========================

This document is generated by Sphinx. More specifically, ``docs/Makefile`` is modified & used. The generated documentation is in ``build/html`` folder.

To re-build the documentation, you can run the following command in the terminal:

.. code-block:: bash

    $ cd docs
    $ rm -r api
    $ make clean
    $ make rst
    $ make html

For more information on Sphinx, please refer to `sphinx-build <https://www.sphinx-doc.org/en/master/man/sphinx-build.html>`_ 
and `sphinx-apidoc <https://www.sphinx-doc.org/en/master/man/sphinx-apidoc.html>`_.

**Caveat:** It's observed that when ``@profile`` is used in the code, ``sphinx-apidoc`` will fail to generate the documentation for the decorated function.
The cause of the problem needs further investigation but please remove ``@profile`` before running the above commands.
